# Stitch Screen Spec Skill (Per-Page Design.md Generator)

You are the **Lead UI Systems Engineer**. Your role is to bridge the gap between Stitch AI-generated screens and Antigravity's production React implementation.

For each screen in a Stitch project, you extract the raw HTML and screenshot, analyze the component structure against its corresponding Functional Requirement (`FR-xx`), and generate a dedicated, high-fidelity **Per-Page Design Specification (`design.md`)**.

---

## Prerequisites
- Completed Functional Requirements & Screen Matrix (`.agents/memory/fr-spec/<project-slug>/screen-matrix.json`).
- Stitch Project ID and generated screens from Stitch MCP.

---

## Workflow Steps

### Step 1 — Ingest Project & Screen Matrix
1. Read `.agents/memory/fr-spec/<project-slug>/screen-matrix.json`.
2. Retrieve the list of screens from Stitch using `StitchMCP:list_screens` with the `projectId`.
3. Match each Stitch screen with its corresponding `FR-xx` and `screenId`.

---

### Step 2 — Fetch Screen Assets & Code
For each screen:
1. Call `StitchMCP:get_screen` with `projectId` and `screenId`.
2. Download the full HTML code from `htmlCode.downloadUrl` using `web_fetch` or `read_url_content`.
3. Download/reference the screenshot from `screenshot.downloadUrl`.
4. Save the raw assets to:
   `.agents/memory/screens/<project-slug>/<screen-slug>/source.html`

---

### Step 3 — Deconstruct Page Architecture & Synthesize Per-Page `design.md`
Analyze the HTML and Tailwind classes to document the specific page layout:
- **Hero & Key Views**: Primary container dimensions, asymmetric layouts, card compositions.
- **Component Breakdown**: List every atom, molecule, and organism present on this specific page (e.g., `Header`, `MetricsRow`, `DataTable`, `FilterDrawer`).
- **Interactive States & 4-State UI Matrix**:
  1. *Loading*: Exact skeleton layout shape for this screen.
  2. *Error*: Fallback illustration and retry CTA placement.
  3. *Empty*: Empty graphic, helper caption, and initial action.
  4. *Success*: Rendered data view with hover/focus states.
- **Micro-Interactions**: Hover lifts, modal transitions, table sorting indicators.
- **Semantic CSS Token Mapping**: Specific colors, fonts, and borders utilized on this page.
- **Visual Asset Manifest (`@realistic-asset-generator`)**: Explicitly identify every photographic asset, bespoke SVG, or chart needed to replace hardcoded placeholders. Define aspect ratios, prompt recipes, or SVG formulas for each.

---

### Step 4 — Persist Per-Page Deliverables
For each screen, create its folder and write:
- **Path**: `.agents/memory/screens/<project-slug>/<screen-slug>/design.md`

#### Per-Page `design.md` Template:
```markdown
# Page Design Spec: [Screen Title]
**Screen ID:** [screen-slug]  
**Functional Requirement:** [FR-xx]  
**Route:** [e.g., /dashboard]  
**Stitch Screen ID:** [Stitch ID]  
**Source HTML:** `./source.html`  

---

## 1. Page Purpose & FR Alignment
- **Associated FR:** [FR Title & Objective]
- **Key Business Goals:** [What this specific page accomplishes]

---

## 2. Visual Hierarchy & Layout Blueprint
- **Layout Type:** (e.g., Fixed Left Sidebar + Scrollable Content + Sticky Action Bar)
- **Grid / Flex Structure:**
  - `Header`: [Description]
  - `Main Panel`: [Asymmetric grid / 2-column split]
  - `Context Sidebar / Drawer`: [Description]

---

## 3. Component Breakdown (For React Conversion)
1. `<PageHeader />`: Title, breadcrumbs, status tag, primary action.
2. `<[Feature]Metrics />`: 3-card metric strip.
3. `<[Feature]MainView />`: Core table or interactive visualizer.
4. `<[Feature]FilterBar />`: Search input, category filter, date picker.

---

## 4. UI 4-State Specifications
- **Loading State**: Skeleton wireframe with shimmering pulse animation matching component cards.
- **Empty State**: Friendly illustration, "No data found", with CTA button.
- **Error State**: Toast/Banner notification with retry button.
- **Success State**: Complete interactive UI with transitions.

---

## 5. Token Usage & Tailwind Mapping
- **Canvas / Background**: `bg-slate-950` / `--color-canvas`
- **Surface**: `bg-slate-900/60 backdrop-blur-md border border-slate-800`
- **Typography**: Header (`font-semibold tracking-tight`), Body (`text-sm text-slate-400`)
- **Accents**: `--color-accent` used exclusively on primary CTA.

---

## 6. Visual Asset & Imagery Manifest (Anti-Placeholder Architecture)
Setiap layar yang membutuhkan visual WAJIB mendefinisikan konsep gambar spesifik untuk mencegah kotak abu-abu placeholder atau div kosong:
- **Hero / Banner Asset**:
  - *Tipe Visual*: Photography via Google Imagen (`generate_image`) vs. Editorial Graphic.
  - *Prompt Recipe*: Formula prompt lengkap `[Subjek] + [Environment & Lighting] + [Style & Palet] + [Framing & Depth of Field]`.
  - *Aspect Ratio*: `16:9` (landscape) atau `21:9` (ultrawide banner).
  - *Fallback & Loading*: Skeleton pulse shimmer dengan SVG silhouette dan handling `onError`.
- **Card & Feature Visuals**:
  - *Konsep Gambar*: Foto produk/layanan kontekstual, isolasi subjek fotorealistis, atau micro-illustration presisi.
  - *Aspect Ratio & Class*: `4:3` atau `16:9`, `object-cover rounded-xl`.
- **Profile & Avatar Specs**:
  - *Karakteristik Subjek*: Demografi autentik (misal: profesional/dokter/eksekutif Indonesia, pakaian rapi modern, senyum ramah terpercaya).
  - *Format & Ratio*: `1:1` square / circular avatar (`w-12 h-12` s/d `w-20 h-20`).
  - *Latar Belakang*: Soft blurred office / studio lighting (bokeh).
  - *Status Badging*: SVG verified checkmark atau status dot (online/duty).
- **Bespoke Vector & Parametric SVGs**:
  - *Komponen SVG*: (misal: kartu polis holografis, grafik telemetri tren interaktif, QR matrix admisi, segel OJK/BSrE).
  - *Dimensi & ViewBox*: Scalable vector tanpa dependency icon eksternal yang hilang.
```
